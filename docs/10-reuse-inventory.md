# 10 — Інвентаризація: що беремо і звідки

## 10.1 Карта донорів

| Репозиторій | Що це | Роль тут |
|---|---|---|
| `../sdr-ground` | Приймач FPV на Neptune, доведений до картинки | **Платформа**: bring-up, board target, пінаут, інструменти |
| `../wy-lora` | LoRa-FHSS модем на Pluto, перевірений в емуляторі | **Ідеї протоколу**: TDMA, епоха, консенсус, FastLock |
| `../maia-sdr` | Форк maia-sdr (HDL + httpd) | **DSP-бібліотека** в Amaranth |
| `../sdrview` | Форк tezuka_fw | Buildroot-каркас (через sdr-ground) |

## 10.2 З `sdr-ground` — беремо як є

Це найцінніше, бо це **перевірене на цій самій платі**.

| Що | Шлях | Нотатка |
|---|---|---|
| Board target | `board/neptune/` | Overlay, init, U-Boot env. Бут 45 с |
| **XDC з реальним пінаутом** | `vendor/neptunesdr-xdc/p210-readback-constr.xdc` | **Найдорожчий артефакт обох проектів** |
| DTS, `ps7_init` | `board/neptune/` | DDR 32-біт, GbE, W25Q256 |
| Buildroot external tree | `configs/`, `package/`, `external.mk` | Збірка образу |
| Kernel module | `software/maia-kmod/` | DMA-інтерфейс до PL → основа `sdrmesh-kmod` |
| HTTP-сервіс, скелет | `software/maia-httpd/` | Axum, WS, API-патерн → `sdrmesh-httpd` |
| Клієнт egui | `app/` | Патерн монітора; тут — карта сузір'я |
| Інструменти збірки | `tools/fw/build-neptune.sh` | Включно з обхідними шляхами по WSL |
| **Інструменти плати** | `tools/board/p210-live-run.sh`, `miso-sweep.sh` | Завантаження бітстріму в живу систему |
| Serial-консоль | `tools/serial/reboot-run.ps1` | Віддалений ребут з командами U-Boot |
| Релізна упаковка | `tools/release.sh` | Архів із клієнтом і SD-файлами |

### Інженерні пастки, за які вже заплачено

Ці чотири рядки — причина читати `sdr-ground/docs` перед першим комітом тут:

| Пастка | Де описано | Симптом, якщо не знати |
|---|---|---|
| Чужий XDC під «neptunesdr» неправильний | `23` | AD9361 не відповідає. Ціна: тиждень |
| **EMIO GPIO має бути підключений** | `22` | `ad_iobuf` сам глушить двонапрямні лінії, MISO читається як 0xFF |
| **DMA-адреса 29-бітна на 1 ГБ** | `24` | IQ приходить нулями |
| Buildroot тихо переюзає старий бінарник | `34.6` | Правки не потрапляють в образ |
| `\|\| true` у патчі ховає провал накладання | `23.3` | Збірки без потрібного фікса, і ніхто не знає |
| `max-speed = <100>` у DTS | `23.4` | Гігабіт не піднімається |

## 10.3 З `maia-sdr` — DSP-бібліотека

Amaranth-модулі, що переюзаються майже без змін:

| Файл | Що дає |
|---|---|
| `fir.py`, `channel_fir.py` | RRC-фільтри, дециматори/інтерполятори |
| `cordic.py` | Корекція CFO, фазові обертання |
| `fft.py`, `spectrometer.py` | Scout-свіп вікна (07.5) |
| `ddc.py` | Цифровий down-converter |
| `recorder.py` | raw-IQ у DDR — діагностичний харнес (09.4, крок 3) |
| `pluto_platform.py` + інфраструктура збірки | Каркас Amaranth-проекту під Zynq |

**Не беремо:** `fm_demod.py` і весь кольоровий CVBS-ланцюг (`burst_*`,
`chroma_*`, `per_line_rotate`, `line_comb`, `yuv_to_rgb`) — це про відео.
`peak_detector.py` — не потрібен.

> Побічний виграш: ці модулі вже збирались і працювали **на цій платі**
> (sdr-ground, фази 2–5), тож їх поведінка у кремнії відома.

## 10.4 З `wy-lora` — ідеї, не код

> [!] **Важливе застереження.** wy-lora валідований **UDP-емулятором**
> (`crates/wy-hal/PlutoEmulator`), а не в ефірі. Усі заявлені PDR 100%,
> дальності і стійкості до РЕБ — це поведінка емулятора. Код під Pluto
> (7010, 1R1T, AD9364) нам не підходить архітектурно. Переносимо **рішення**,
> а не реалізацію і не числа.

### Беремо беззастережно

| Ідея | Де в wy-lora | Де в нас |
|---|---|---|
| **Epoch Authority**: єдине джерело часу в заголовку | ARCHITECTURE 4.5, лог проблема 2 | 05.5 |
| **Step latch**: частоти нерухомі N суперфреймів | лог проблема 4 | 05.5 |
| **Flywheel clock**: пропустив кадр → +1, фазу зберіг | лог проблема 4 | 05.5 |
| **Шахова ротація**: один сектор із чотирьох за раз | ARCHITECTURE 4.4 | 05.7 |
| **Ансамблеве голосування** 5 оцінювачів + анти-флапінг | ARCHITECTURE 4.3 | 07.4 |
| **Консенсус із пріоритетом слабшого кінця** | ARCHITECTURE 4.2 | 07.5 |
| **28-байтний вектор чистих каналів** у телеметрії | ARCHITECTURE 4.2 | 07.5 |
| **Rendezvous від пас-фрази**, 16 опорних частот | ARCHITECTURE 4.6 | 05.6 |
| **Межі діапазону в заголовку** → zero-config | лог етап 21 | 03.5 (+хеш профілю) |
| **Make-before-break** міграція між сітками | лог етап 22 | 05.7 |
| **Anti-replay**: монотонний лічильник + вікно | лог проблема 8 | 07.6 |
| **MIC на кадрі** (Poly1305) | ARCHITECTURE 6.А | 4.6 |
| FastLock-кеш профілів синтезатора | ARCHITECTURE 3.2 | 05.7, 08.1 |
| Апаратний DPLL за преамбулою | ARCHITECTURE 4.6.3 | 05.4 |
| RS-стирання через паралельні канали | ARCHITECTURE, RS(2,2) | 4.5 (адаптовано на послідовні слоти) |

### Беремо з переробкою

| Ідея | Що міняємо і чому |
|---|---|
| 4 сектори по 300–6000 МГц | У нас одне PA-вікно ≥1 ГГц → сектори в межах вікна, рознос ≥250 МГц (3.5) |
| Суперфрейм 100 мс / 8 слотів | 20 мс / 20 слотів — IP і TCP не терплять 200 мс RTT (05.2) |
| LoRa CSS як PHY | DSSS для службового шару + однонесуча для даних (04.3). CSS не масштабується до 4 Мбіт/с і погано дає часову мітку |
| Master/Slave | Симетричні вузли; «мастер» — лише роль джерела часу, і вона обирається (05.3) |
| Guard 4.5 мс у слоті | 100 мкс — на два порядки менше, бо слот 1 мс, не 12.5 |
| CRSF як транспорт | IP-труба; CRSF — просто один потік у ній |

### Беремо як перелік того, чого не робити

Журнал wy-lora цінний саме провалами. Ці шість — наш чекліст на фазу 1:

| № | Провал | Урок для нас |
|---|---|---|
| 1 | Захардкоджений `"pdr": "100.0"` | **Жодна метрика не має права бути константою.** 11.4 |
| 2 | Дрейф таймерів ОС на 20–30 хв | Час не в `tokio::sleep`, а в PL-таймері |
| 5 | 1-бітний DDS → позасмугові гармоніки | Синусоїдальна LUT із самого початку |
| 7 | FastLock-таймер 2 мкс замість 25 мкс | **Паспортні числа читати, а не вгадувати** |
| 9 | Емулятор приймав пакети з будь-якої частоти | Тест, що не може провалитись, нічого не доводить |
| 12 | Фазовий дрейф мікрослотів | DPLL обов'язковий, не опційний |

## 10.5 Сторонні компоненти

| Що | Ліцензія | Роль |
|---|---|---|
| **openwifi** | AGPL-3.0 [?] перевірити | Трек A (04.1). [!] AGPL — подумати про наслідки до того, як вкладатись |
| `babeld` | MIT | Маршрутизація (06.2) |
| ADI HDL (`axi_ad9361` та ін.) | ADI BSD-подібна | Інтерфейс до трансівера |
| Viterbi / RS ядра | за вибором | FEC (4.5). Шукати BSD/MIT |
| `chacha20poly1305`, `rand_chacha` (Rust) | Apache/MIT | Крипто, як у wy-lora |

> [!] **Ліцензія openwifi — питання, яке треба закрити рано.** Якщо це AGPL,
> а трек A має стати основою чогось закритого — буде проблема. Але трек A
> у плані свідомо є лесою, а не будинком (04.1), і це додатковий аргумент
> не зрощувати з ним трек B.

## 10.6 Що ми робимо з нуля

Чесний перелік, щоб обсяг не виглядав меншим, ніж є:

| Компонент | Оцінка складності |
|---|---|
| RX-тракт у PL (синхронізація, еквалайзер, демодуляція) | **Найбільша частина проекту** |
| TX-тракт у PL | Велика |
| `sdrmesh-d`: планувальник, метрики, адаптація, фрагментація | Велика |
| Beamformer 2×RX | Середня, але унікальна для цієї плати |
| Інтеграція FEC | Середня |
| PL-таймер + DPLL + слотовий автомат | Середня |
| Стенд і методика замірів (11) | Середня, і робити **першою** |
