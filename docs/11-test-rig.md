# 11 — Стенд і методика замірів

> Цей документ навмисно стоїть **перед** роадмапом. Обидва донорські проекти
> зійшлись на одному висновку з протилежних боків: sdr-ground втратив тижні
> на хибних вимірюваннях (`docs/37` — «діапазони були в передавачі»), а
> wy-lora отримав архітектуру, яка красиво працює в емуляторі і ніколи не
> перевірялась у ефірі. Стенд — не допоміжна задача, а перший продукт.

## 11.1 Кабельний стенд

Польовий замір нерепродуктивний: змінюється погода, положення, ефір. Усе, що
можна перевірити по кабелю, перевіряється по кабелю.

```
  ┌──────────┐                                        ┌──────────┐
  │ Neptune  │ TX1 ──► [ атт. 30 дБ ] ──┐          ┌──► RX1 │ Neptune  │
  │   N1     │                          │          │         │   N2     │
  │  (ГС)    │ RX1 ◄── [ атт. 30 дБ ] ◄─┤ combiner ├─◄── TX1 │  (борт)  │
  └──────────┘                          │  / split │         └──────────┘
                                        │          │
  ┌──────────┐                          │          │
  │ Neptune  │ TX2 ──► [ атт. кер. ] ───┘          │  ← джамер
  │   N0     │                                     │
  │ (джамер) │ RX2 ◄───────────────────────────────┘  ← аналізатор
  └──────────┘
```

| Елемент | Для чого |
|---|---|
| Керований атенюатор (0–60 дБ, кроками) | **Імітація дальності.** Кожні 6 дБ = подвоєння відстані |
| Фіксовані атенюатори 30 дБ | Захист входів |
| Combiner / splitter | Додавання завади в тракт |
| Генератор шуму (або TX2 з шумом) | Контрольований SNR → BER-крива |
| **N0 (плата з sdr-ground)** | Джамер і спектроаналізатор, уже заведений |

Що це дає: **крива BER vs SNR, знята за 10 хвилин і повторювана наступного
дня з тим самим результатом.** Без неї будь-яке «стало краще» — здогадка.

## 11.2 Що міряється на стенді, а що тільки в полі

| На стенді (кабель) | Тільки в полі |
|---|---|
| BER / PER vs SNR для кожного MCS | Реальна дальність |
| Чутливість приймача | Діаграма антен, поляризаційні втрати |
| Час перестроювання FastLock | Доплер від руху |
| Джиттер мітки слота | Багатопроменевість від рельєфу |
| Час TDD-перемикання | Тепло в реальному корпусі на сонці |
| Глибина нуля beamformer-а | Поведінка при маневрі борта |
| Пропускна здатність, RTT, перебудова маршруту | Радіогоризонт |
| EVM по сітці частот вікна (3.6) | Реальна завадова обстановка |
| Поведінка під керованою завадою, J/S | РЕБ противника |

Правило: **у поле виїжджаємо лише з тим, що на стенді вже працює і зміряне.**
Поїздка в поле коштує день; прогін на стенді — хвилини.

## 11.3 A/B-харнес: raw-IQ

Найцінніший інструмент, прямо з досвіду sdr-ground (`4.4`: «під час bring-up
це найцінніший інструмент»):

- PL пише сирий IQ у DDR (`recorder.py` з maia-hdl)
- `sdrmesh-httpd` віддає захват по HTTP (`/raw_iq?ch=1&n=...`)
- на хості той самий демодулятор збирається як standalone і жує файл

Навіщо: **перезбірка бітстріму = 40 хвилин, ітерація демодулятора на хості =
секунди.** Демодулятор однонесучої з еквалайзером і синхронізацією складніший
за CVBS-декодер, тож економія буде ще більшою.

Правило, яке з цього випливає: **алгоритм спершу пишеться і доводиться на
хості на реальних захватах, і лише потім переноситься в PL.** Жодного
«напишу в Amaranth і подивимось».

Друга половина харнесу — **IQ-плейбек**: PL вміє не лише писати, а й
*відтворювати* записаний IQ у TX. Це дає повторюваний вхід для приймача:
один і той самий сигнал, той самий шум, той самий результат. Без цього
порівняння двох версій демодулятора нічого не означає.

## 11.4 Метрики, яким можна вірити

Прямий урок wy-lora (проблема 1: `"pdr": "100.0"` захардкоджений, і місяцями
показував успіх на мертвому лінку).

**Правила:**

1. **Жодна метрика лінку не обчислюється з власних даних вузла.** PDR, PER,
   RTT — тільки за фактом підтверджень від кореспондента.
2. **Кожна метрика має джерело і час.** Структура метрики несе
   `{value, measured_at_epoch, source_node_id}`. Метрика старша за 1 с
   показується як «немає даних», а не як останнє відоме значення.
3. **Жодного значення по замовчуванню, що виглядає як успіх.** Невідомий
   PDR — це `None`, і в UI це порожнє поле, а не 100%.
4. **Ковзне вікно, не накопичувальний середній.** PDR за останні 50
   суперфреймів (1 с), як у wy-lora після фіксу.
5. **Тест, що не може провалитись, видаляється.** Емулятор wy-lora приймав
   пакети з будь-якої частоти (проблема 9) — і всі тести «проходили».

## 11.5 Три рівні перевірки

| Рівень | Що перевіряє | Швидкість |
|---|---|---|
| **Юніт / симуляція** | Amaranth-модулі в `cocotb`/pytest, Rust-логіка | секунди |
| **Канальна модель на хості** | Повний TX→канал(AWGN+CFO+затримка+завада)→RX ланцюг у софті | хвилини |
| **Стенд** | Те саме на залізі по кабелю | хвилини |
| **Поле** | Усе разом | день |

Рівень «канальна модель на хості» — це те, чого бракувало wy-lora: там був
емулятор **транспорту** (UDP-сокети), а не емулятор **каналу**. Емулятор
транспорту не може виявити ні проблему синхронізації, ні деградацію під
шумом — тобто рівно те, через що модеми не працюють.

У нас модель каналу зобов'язана включати: AWGN, зсув несучої, зсув часу,
доплер, і хоча б один тип завади. Той самий Rust-код демодулятора має
проходити і модель, і стенд.

## 11.6 Журнал замірів

Як у sdr-ground (`docs/14-board-survey.md`, 94 КБ сирих вимірювань):
**кожен замір записується з умовами, і спростовані висновки не видаляються,
а помічаються як спростовані.** Там це дало можливість повернутись і
побачити, що висновок «гігабіт маргінальний» (14-I.2) був хибним і чому.

Формат запису одного заміру:

```
### 2026-11-05 / BER vs SNR, MCS1, стенд
Умови: N1 TX1 → атт.42дБ → N2 RX1, шум від N0 TX2, вікно gan-05-25, f=1500 МГц
Бітстрім: a3f91c2  Прошивка: 0.1.4-rc2
Результат: [таблиця]
Висновок: 1.8 дБ гірше за теорію
Відкрито: чи це еквалайзер, чи timing recovery — розділити наступним прогоном
```

Без `Умови` і версій запис нічого не вартий.
