## 8.3 Чому Rust на ARM і чому tokio

Обидва донори вже на цьому стоять (sdr-ground `maia-httpd`, wy-lora `wy-daemon`),
і причина не мода:

- **Немає GC** → немає непередбачуваних пауз у планувальнику слотів
- Крос-компіляція під `armv7-unknown-linux-gnueabihf` відпрацьована в обох проектах
- Один бінарник, жодних рантаймів на платі

Бюджет CPU (оцінка, Cortex-A9 667 МГц × 2 ядра). Суперфрейм 20 мс = 13.3 млн
тактів на ядро:

| Задача | Оцінка на суперфрейм |
|---|---|
| Планувальник + карта слотів | ~10 мкс |
| Метрики, голосування, анти-флапінг | ~20 мкс |
| Poly1305 MIC на 4 Мбіт/с | ~400 мкс [?] заміряти |
| RS-стирання по слотах | ~50 мкс |
| tun ↔ фрагментація ↔ DMA | ~500 мкс [?] заміряти |
| **Разом** | **~1 мс із 20 (5%)** |

> [!] Числа wy-lora у цій таблиці («0.24% завантаження») стосувались модема
> без IP-труби і без криптографії на 4 Мбіт/с. Наші два рядки з [?] — саме ті,
> що можуть виявитись у 10 разів гіршими, і їх треба міряти рано,
> а не вірити оцінці.

## 8.4 Зовнішні інтерфейси вузла

| Інтерфейс | На ГС | На борту |
|---|---|---|
| Ethernet | Основний: mesh0 маршрутизується в LAN | Не задіяний (або до камери/компаньйона) |
| UART | Консоль (FT2232) | Консоль + **CRSF/MAVLink до польотника** |
| USB-C | JTAG + консоль | Те саме |
| microSD | Образ + конфіг + логи | Те саме |
| HTTP/WS :8000 | API, метрики, карта сузір'я | Той самий API (доступний по mesh!) |
| GPIO | **PPS від атомного еталона** | — |

Важливий наслідок: оскільки mesh несе IP, **API борта доступний із землі
через mesh**. Тобто налагоджувати борт у повітрі можна тими самими запитами,
що на столі. Це велика перевага IP-транспорту, і її варто використати:
логи, метрики, навіть захват IQ — усе через ту саму трубу (на низькому
пріоритеті, щоб не з'їдати канал).
