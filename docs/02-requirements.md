# 02 — Вимоги і похідні від них числа

## 2.1 Функціональні

| № | Вимога | Звідки |
|---|---|---|
| F1 | Назовні вузол = мережевий інтерфейс з IP-адресою | «універсальний транспорт» |
| F2 | Будь-який вузол досяжний з будь-якого іншого, якщо існує хоч один шлях | «повний mesh» |
| F3 | Маршрут перебудовується без розриву TCP-сеансів | PoC-критерій (00) |
| F4 | Швидкість адаптується до умов, від «ледь живого» до «комфортного» | IP-труба |
| F5 | Частотне вікно і сітка каналів задаються конфігурацією і змінюються по ефіру | «діапазон під PA, налаштовується» |
| F6 | Вузол стартує без ручного налаштування, маючи лише пас-фразу сузір'я | ідея wy-lora (Zero-Config) |
| F7 | Сузір'я працює без GNSS | атомний еталон на землі замість GPS-синхронізації |
| F8 | Будь-яка ГС може бути точкою входу; втрата однієї ГС не рве мережу | «кілька ГС» |

## 2.2 Числові цілі PoC

Цілі, а не прогнози. Прогнози — у 03, і вони зійдуться з цими числами лише
після заміру.

| Параметр | Ціль PoC | Ціль продукту |
|---|---|---|
| Вузлів | 3 | 8–16 |
| Хопів | 2 | 3–4 |
| Швидкість, 1 хоп, близько | ≥ 2 Мбіт/с | 4 Мбіт/с |
| Швидкість, 2 хопи, далеко | ≥ 100 кбіт/с | 300 кбіт/с |
| Мінімальна робоча швидкість | 20 кбіт/с | 20 кбіт/с |
| RTT, 1 хоп | ≤ 30 мс | ≤ 20 мс |
| RTT, 2 хопи | ≤ 60 мс | ≤ 40 мс |
| Час перебудови маршруту | ≤ 2 с | ≤ 0.5 с |
| Час первинного захоплення лінку | ≤ 5 с | ≤ 1 с |
| Дальність, борт↔земля | 10 км (LOS, у полі) | 50–100 км |
| Дальність, борт↔борт | 5 км | 30 км |

> [!] **RTT і TDMA конфліктують.** Слотована схема додає затримку
> ≈ довжина суперфрейму на хоп. Суперфрейм 20 мс → 2 хопи ≈ 40 мс лише на
> чергування слотів. Це прямо визначає вибір довжини суперфрейму в 05.

## 2.3 Що означає «адаптивна швидкість» у числах

Не один режим, а драбина. Кожен щабель — окремий MCS (04.4), і вузол їздить по
ній у реальному часі за оцінкою SNR і PER.

```
    4 Мбіт/с ┤ ████ 16QAM 3/4,  4 МГц       близько, чисто
    2 Мбіт/с ┤ ███  8PSK 2/3,   4 МГц
    1 Мбіт/с ┤ ███  QPSK 1/2,   2 МГц
  400 кбіт/с ┤ ██   QPSK 1/2,   1 МГц
  100 кбіт/с ┤ █    BPSK 1/2,   250 кГц
   20 кбіт/с ┤ ▌    BPSK 1/2 + spread×16     далеко / під завадою
             └────────────────────────────────────────────────
```

Нижній щабель працює на **негативному SNR** за рахунок розширення спектру — це
той самий механізм, що в LoRa, і він же несе службовий трафік (04.3).

## 2.4 Нефункціональні

| Вимога | Числом |
|---|---|
| Споживання бортового вузла | ≤ 12 Вт разом з FEM [?] перевірити на платі |
| Маса бортового вузла | Neptune + FEM + радіатор, [?] зважити |
| Робоча температура | −20…+60 °C [!] комерційні плати часто від 0 °C (sdr-ground/12.6) |
| Детермінізм таймінгу слотів | джиттер мітки слота ≤ 1 мкс |
| Холодний старт до першого пакета | ≤ 60 с (включно з бутом Linux ~45 с) |

> [!] **Бут 45 с** успадкований від sdr-ground. Для борта це означає: вузол має
> бути живий **до** зльоту, перезавантаження в повітрі = втрата лінку на хвилину.
> Варіант лікування — watchdog на рівні сервісу, а не перезавантаження системи.

## 2.5 Чого mesh насправді коштує

Прямо з арифметики TDMA, щоб не було розчарувань на фазі 4:

- Кожен хоп **займає власний слот**. Трафік через 2 хопи з'їдає **подвійний
  ефірний час** на тій самій ділянці мережі.
- Ретрансляція — це store-and-forward: затримка складається.
- Повний mesh на N вузлів має N(N−1)/2 потенційних ланок, і метрика по кожній
  має якось оновлюватись. На 3 вузлах це 3 ланки, на 16 — 120.

Висновок, який варто пам'ятати ще на етапі плану: **«4 Мбіт/с» — це про один
хоп на близькій відстані, і ніколи про весь mesh одночасно.** Таблиця 2.2
саме тому розділена на «1 хоп» і «2 хопи».
