# 12 — План по фазах

Кожна фаза має **критерій виходу**. Не переходимо далі, доки він не виконаний —
правило з sdr-ground, і воно там себе виправдало.

Фази 0–2 — трек A (швидкий ефір на openwifi). Фази 3–6 — трек B (своя PHY).
Обґрунтування розділення — 04.1.

---

## Фаза 0 — Платформа, час, залізо 🔲

Нічого з цього не вимагає своєї PHY, і майже все можна робити вже зараз на
**одній** платі, що вже є.

1. [ ] Форк board target `neptune` із sdr-ground → бутиться на нашому образі
2. [ ] **TX-тракт: перший тон.** DDS у PL → `TX1` → спектроаналізатор.
       Заміряти потужність і гармоніки по всьому вікну
3. [ ] **ENSM / TDD**: заміряти час переходу RX↔TX на залізі
4. [ ] **FastLock**: заміряти реальний час перестроювання на стрибках
       10 / 100 / 500 МГц. Паспорт каже <30 мкс — перевірити
5. [ ] **PPS у PL**: атомний еталон → GPIO → PL-таймер. Заміряти джиттер мітки
6. [ ] Дослідити **шлях B** (01.3): знайти TCXO на платі, з'ясувати чи є
       можливість інжекції 10 МГц / VCTCXO-керування
7. [ ] **Когерентність 2×RX після FastLock** (07.2, відкрите питання):
       один тон через дільник на обидва входи, стрибки LO, дивитись фазу
8. [ ] Зібрати **стенд** (11.1): атенюатори, combiner, N0 як джамер
9. [ ] Замовити/зібрати: 3 плати, PA, LNA/FEM, антени, атомний еталон
10. [ ] EVM по сітці частот вікна (3.6) — чи тримається калібрування

**Вихід:** TX працює і зміряний; таймінг-числа (guard 100 мкс із 05.2)
підтверджені або переписані; стенд стоїть; відповідь на питання
«беамформінг сумісний з ППРЧ?».

> Пункти 2–7 — це фактично **інвентаризація того, чого sdr-ground не чіпав**
> (01.3). Вони дешеві і закривають найбільше невизначеності на одиницю часу.

---

## Фаза 0b — Профіль діапазону 🔲 паралельно

1. [ ] Обрати PA → виміряти його смугу, потужність, duty cycle, ККД
2. [ ] Обрати LNA/FEM → виміряти NF і узгодження
3. [ ] Антени: широкосмугова направлена на ГС, омні на борт
4. [ ] Заповнити профіль (3.5) **зміряними**, а не паспортними числами
5. [ ] Перерахувати бюджет 3.3 на реальних числах

**Вихід:** файл профілю з усіма полями, де жодне число не взяте з даталиста
без перевірки.

---

## Фаза 1 — Трек A: перший ефір і перший mesh 🔲

Мета — працююча IP-mesh на справжньому залізі **якомога раніше**, щоб усе
системне (PA, антени, тепло, маршрутизація, UI, стенд) перевірялось паралельно
з розробкою своєї PHY, а не після неї.

1. [ ] Порт openwifi на Neptune: підміна XDC на наш пінаут (01.1)
2. [ ] Один вузол: `mac80211` піднімається, видно сканування
3. [ ] Два вузли: ad-hoc / 802.11s лінк по кабелю через атенюатор
4. [ ] `iperf3` і `ping` по радіо; крива пропускної vs атенюація
5. [ ] Вузькі канали (10 / 5 МГц) — перевірити виграш чутливості [?]
6. [ ] Три вузли + Babel; **штучно заглушити пряму ланку → трафік через релей**
7. [ ] Перший виїзд у поле: дальність на реальних антенах і PA
8. [ ] Тепловий прогін борта в закритому корпусі під трафіком

**Вихід:** **критерій PoC із 00 виконаний** — 3 вузли, 2 хопи, маршрут
перебудовується, TCP не рветься. На openwifi, не на своїй PHY.

> [!] Тут головний ризик проекту: **застрягнути**. Трек A дасть щось робоче,
> і спокуса «допилити його» буде сильною. Протидія — фаза 2 починається
> одразу, і її критерій виходу не має нічого спільного з треком A.

---

## Фаза 2 — Своя PHY: точка-точка по кабелю 🔲

1. [ ] Канальна модель на хості (11.5): TX→AWGN+CFO+затримка→RX у Rust
2. [ ] raw-IQ харнес у PL: захват і **плейбек** (11.3)
3. [ ] TX-тракт у PL: мапер + RRC + DDS, MCS1 (QPSK 1/2)
4. [ ] RX-тракт у PL: AGC, CFO, matched filter, timing recovery, демапер
5. [ ] FEC: згортковий + Viterbi + RS (4.5)
6. [ ] **BER vs SNR на стенді** для MCS1
7. [ ] Решта драбини MCS (4.4), BER-крива для кожного щабля
8. [ ] DSSS-шар і детектор преамбули
9. [ ] Еквалайзер

**Вихід:** крива BER vs SNR **у межах 1.5 дБ від теорії** для кожного MCS,
знята на стенді і повторювана. Звіт утилізації PL із реальними числами
проти оцінки 09.2.

---

## Фаза 3 — TDMA, час, ППРЧ 🔲

1. [ ] PL-таймер суперфрейму, прив'язаний до PPS; лічильник епохи
2. [ ] Слотовий автомат: TX/RX/guard за розкладом
3. [ ] DPLL за преамбулою; заміряти, як борт тримається за землею
4. [ ] Епоха в заголовку, step latch, flywheel (05.5)
5. [ ] Rendezvous від пас-фрази (05.6); заміряти час захоплення
6. [ ] FastLock-профілі, ППРЧ у межах сектора
7. [ ] Зміна сектора на межі суперфрейму (3.6)
8. [ ] Адаптація MCS з анти-флапінгом (4.4)
9. [ ] **Прогін під керованою завадою з N0**: spot, барражна, follower

**Вихід:** два вузли тримають лінк під spot-джамером (частота джамера
фіксована, ми стрибаємо); MCS адаптується і **не флапає**; холдовер борта
зміряний; час захоплення ≤5 с.

---

## Фаза 4 — IP і mesh на своїй PHY 🔲

1. [ ] `sdrmesh-kmod` + `tun`-інтерфейс `mesh0`
2. [ ] Фрагментація і динамічний MTU (06.4)
3. [ ] `iperf3` по своїй PHY, 2 вузли
4. [ ] Таблиця сусідів з beacon-слотів; метрика → babeld (06.2)
5. [ ] Централізований планувальник слотів на ГС (05.3)
6. [ ] Три вузли, 2 хопи, перебудова маршруту
7. [ ] RS-стирання по слотах (4.5)
8. [ ] Друга ГС: вибори мастера часу, два шлюзи (06.5)

**Вихід:** критерій PoC із 00, але **на своїй PHY**. Плюс: цифри з 2.2
(швидкість, RTT, час перебудови) зміряні і записані.

## Фаза 5 — Завадостійкість 🔲

1. [ ] Beamformer 2×RX у PL (07.2)
2. [ ] Оцінка $R_{nn}$ у тихих інтервалах, розрахунок ваг
3. [ ] **Заміряти глибину нуля** проти джамера на стенді
4. [ ] Scout-слоти: FFT-свіп вікна, карта чистих каналів
5. [ ] Голосування за частоти, 5 оцінювачів (07.4)
6. [ ] Консенсус між вузлами, 28-байтний вектор (07.5)
7. [ ] Шахова ротація секторів (05.7)
8. [ ] Anti-replay і MIC (07.6) — якщо не зроблено у фазі 3
9. [ ] Режим радіомовчання борта (07.6)
10. [ ] LDPC замість згорткового, **якщо** запас DSP дозволив (09.3)

**Вихід:** зміряна в дБ стійкість: J/S, при якому лінк живий, для кожного
типу завади, з beamformer-ом і без. Це головне число всього проекту.

## Фаза 6 — Поле і сузір'я 🔲

1. [ ] Монтаж бортових вузлів у літаки; вібрація, тепло, живлення
2. [ ] Міст до польотника (CRSF/MAVLink) поверх IP
3. [ ] Клієнт-монітор сузір'я: топологія, метрики ланок, карта спектру
4. [ ] Польоти: дальність 1 хоп, потім 2 хопи через релей
5. [ ] Реальна перебудова маршруту в повітрі
6. [ ] Робота без GNSS (F7): перевірити, що нічого не зламалось
7. [ ] Прогін на 8+ вузлів (симуляція + стенд, бо плат не буде)

**Вихід:** зміряна дальність і швидкість у полі; 2 хопи через повітряний
релей працюють; таблиця 2.2 заповнена реальними числами замість цілей.

## 12.1 Що можна робити вже зараз, не чекаючи нічого

| Задача | Чому не блокується |
|---|---|
| Форк board target, бут свого образу | Плата є і заведена |
| TX-тон, ENSM, FastLock, PPS, когерентність (фаза 0, п.2–7) | Одна плата, свій бітстрім уже працює |
| Стенд (11.1) | Потрібні атенюатори, не плати |
| Канальна модель на хості (11.5) | Чистий софт |
| raw-IQ харнес | Є `recorder.py` і досвід sdr-ground |
| Вибір PA і антен, фаза 0b | Закупівля — довгий цикл, починати першим |
| Порт openwifi (фаза 1, п.1–2) | Одна плата |

**Найкраща перша дія:** фаза 0, пункти 2 і 7 — TX-тон і когерентність після
FastLock. Перший каже, чи взагалі працює передача на цій платі (жодного
свідчення немає). Другий визначає, чи сумісні два головні механізми
завадостійкості, чи їх доведеться вибирати. Обидва відповідають на питання,
від яких залежить решта плану, і обидва робляться на наявному залізі.

## 12.2 Орієнтири за обсягом

Не оцінки в тижнях (вони завжди брехливі), а відносна вага:

```
Фаза 0   ████                  інвентаризація + стенд
Фаза 0b  ███                   залізо, закупівля
Фаза 1   ██████                трек A, openwifi + mesh
Фаза 2   ████████████████      своя PHY ← найбільша частина проекту
Фаза 3   ████████              TDMA і час
Фаза 4   ██████                IP і mesh
Фаза 5   ████████              завадостійкість
Фаза 6   █████                 поле
```

Фаза 2 — половина проекту. Саме тому трек A існує: щоб решта системи не
стояла, поки вона робиться.
